JSON 规则填写说明

使用入口
设置与备份 → 规则管理 → 管理 JSON 规则 → 导入 JSON（可多选）。
Winapp2 在单独卡片管理，可与多个 JSON 文件同时启用。JSON 文件独立保存，不会替换默认库或其他文件。新文件默认关闭，启用后在下次常规扫描生效。

多文件与版本
支持 Schema 1、Schema 2，一次最多选 20 份文件，共最多保存 20 份导入规则。导入前逐项检查，确认后显示每份成功、跳过或失败的原因。格式错误不影响其他有效文件。相同文件重复导入会跳过；内容变化必须提高 Version。
Schema 2 使用 PackId 标识同一规则包，文件改名也可升级。Schema 1 根据文件名建立稳定标识，升级请保持文件名不变并提高 Version。批次中的重复标识会拒绝导入，请只保留每包的一份文件。
每份文件可独立启停、导出、升级、回退或移除。升级保留原启用状态及上一版；回退也恢复上一版文件名。移除只删除规则定义，不处理应用文件或备份。旧版保存的默认 JSON 来源仍保留在列表中，可关闭、导出或回退。

只读预览
选中一份规则，点击只读预览，使用正式扫描器读取候选，显示容量和示例路径，不调用清理器，也不更改主页扫描结果。

Schema 2 示例（UTF-8 .json）
{
  "Schema": 2,
  "PackId": "example-app",
  "Name": "Example App cache rules",
  "Version": "1.0.0",
  "Author": "Your name",
  "Description": "Old diagnostic logs only.",
  "Rules": [
    {
      "Id": "old-logs",
      "Name": "Example App",
      "Group": "软件缓存",
      "Part": "旧诊断日志",
      "MatchNames": [
        "Example App"
      ],
      "ExecutableNames": [
        "Example.exe"
      ],
      "Paths": [
        "%LOCALAPPDATA%\\Example App\\Logs"
      ],
      "ExcludeNames": [
        "accounts"
      ],
      "KeepDays": 14,
      "Conditions": {
        "NamePattern": "*.log",
        "MinAgeDays": 30,
        "MinSizeBytes": 1024,
        "MaxSizeBytes": 104857600
      },
      "Method": "files",
      "Description": "Old diagnostic logs.",
      "Impact": "Historical diagnostics will be lost."
    }
  ]
}

字段
Schema：1 或 2。Schema 2 必须有 PackId 和 Name；Schema 1 不需要增加这些字段，直接导入即可。
PackId / Id：规则包 / 单条规则标识，使用小写字母、数字、连字符。Version 是可比较的版本号。Author、Description 为可选说明。
Name / Group / Part：软件名、分类、项目名。Group 使用“软件缓存”“网页缓存”“开发缓存”，英文界面也使用这些规范值。
MatchNames / ExecutableNames / Publishers / ProductNames / RequireSignature：应用指纹，匹配到实际软件后才展开路径。
Paths：明确缓存、临时或日志目录。支持 %LOCALAPPDATA%、%APPDATA%、%PROGRAMDATA%、%TEMP%、%EXEDIR%、%INSTALLDIR%、%PORTABLEROOT% 与有界 * / ?。禁止绝对路径、..、**、脚本、命令，不扫描 Windows 目录。每层最多展开 256 个目录，单条规则最多 100 个根目录及 100 个应用匹配。
KeepDays：保留最近 7～3650 天，建议至少 14 天。
Conditions（Schema 2，可选）：NamePattern 是文件名通配符；MinAgeDays 是最小年龄天数；MinSizeBytes、MaxSizeBytes 是单文件字节数的闭区间。与 Extensions、FileNameRegex 共同使用 AND 条件，必须全部满足。保留期取 KeepDays 与 MinAgeDays 的较大值；年龄最大 3650 天，大小条件最大 1 TiB。
ExcludeNames / ExcludePaths：额外排除的名称及目录模板；敏感文件保护仍生效。
Method：files / contents，都仅处理安全检查后的文件，保留扫描根目录。Description、Impact 说明用途与删除影响。未知字段被拒绝。Schema 2 不提供绕过这些条件的手动保留项删除。

在线与离线更新
列表中默认规则库的在线更新设置仅影响默认库；需 HTTPS 及内置公钥匹配的发布者签名。其他导入文件通过重新导入更高版本更新。本地未签名文件需确认来源；签名原文保持不变，不改写为其他格式。所有外部规则仅参与常规扫描、高级自选，默认不勾选，清理前先备份。不会因导入自动扫描或删除。

============================================================
English JSON Rule Guide

Open Settings & Backups → Rule management → Manage JSON rules → Import JSON (multiple files). Winapp2 has its own card and can run together with multiple JSON files. Files are stored independently and do not replace the default library. New files start disabled and take effect in the next regular scan.

Import Schema 1 or 2 directly, up to 20 selected files and 20 stored imports. Each file is validated and reported separately; malformed files do not block valid ones. Identical imports are skipped. Changed content requires a higher Version. Schema 2 uses PackId for upgrades even after renaming the file. Schema 1 uses a stable identity based on its filename: keep that name for upgrades. Conflicting IDs in one batch are rejected.

Each file has independent enable, export, upgrade, rollback and remove actions. Upgrades preserve enablement and the previous version. Rollback restores both content and filename. Removing definitions never deletes application files or backups. Previously saved default JSON rules remain in the list. Read-only preview uses the production scanner without cleanup or changes to the main scan.

Schema 2 example:
{
  "Schema": 2,
  "PackId": "example-app",
  "Name": "Example App cache rules",
  "Version": "1.0.0",
  "Author": "Your name",
  "Description": "Old diagnostic logs only.",
  "Rules": [
    {
      "Id": "old-logs",
      "Name": "Example App",
      "Group": "软件缓存",
      "Part": "旧诊断日志",
      "MatchNames": [
        "Example App"
      ],
      "ExecutableNames": [
        "Example.exe"
      ],
      "Paths": [
        "%LOCALAPPDATA%\\Example App\\Logs"
      ],
      "ExcludeNames": [
        "accounts"
      ],
      "KeepDays": 14,
      "Conditions": {
        "NamePattern": "*.log",
        "MinAgeDays": 30,
        "MinSizeBytes": 1024,
        "MaxSizeBytes": 104857600
      },
      "Method": "files",
      "Description": "Old diagnostic logs.",
      "Impact": "Historical diagnostics will be lost."
    }
  ]
}

Schema 2 requires PackId and Name. Schema 1 needs neither and is supported unchanged. IDs use lowercase letters, digits and hyphens. Version must increase for upgrades. Author and Description are optional. Group uses the canonical Chinese values in the example.

MatchNames, ExecutableNames, Publishers, ProductNames and RequireSignature match application fingerprints. Paths must identify explicit cache, temporary or log directories. Variables: LOCALAPPDATA, APPDATA, PROGRAMDATA, TEMP, EXEDIR, INSTALLDIR, PORTABLEROOT. Bounded * and ? are supported; absolute paths, traversal, ** and executable commands are rejected. Windows directories are excluded. Limits: 256 expanded directories per level, 100 roots and 100 matching apps per rule.

KeepDays retains 7–3650 days. Optional Schema 2 Conditions support NamePattern, MinAgeDays, MinSizeBytes and MaxSizeBytes. Sizes are inclusive per-file bytes; all supplied filters, Extensions and FileNameRegex combine with AND. The effective age is the larger of KeepDays and MinAgeDays. Ages are capped at 3650 days and sizes at 1 TiB. ExcludeNames and ExcludePaths add exclusions. Sensitive-file protections remain. Method accepts files or contents; both retain scan roots. Unknown fields are rejected. Schema 2 does not expose manual deletion that bypasses these conditions.

Online settings apply only to the default library, require HTTPS and the built-in publisher signature. Other files update through local reimport of a higher version. Unsigned files require confirmation; signed payloads are stored unchanged. External rules are regular/advanced-only, unchecked by default and backed up before cleaning. Import never starts a scan or deletion.
