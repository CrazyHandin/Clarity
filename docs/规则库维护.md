# Clarity 规则扩展

内置规则、Winapp2、默认 JSON 库与启用的导入文件在常规扫描中合并；快速扫描仅运行内置低风险规则。Winapp2 单独成卡，JSON 默认库与导入文件在同一列表独立管理，重复候选文件按路径去重。

## JSON 处理流程

- RulePackParser：大小限制、签名验证、字段结构解析，兼容 Schema 1 与 Schema 2，未知字段拒绝载入。
- RulePackValidator：应用指纹、路径变量、保留期、文件名及大小边界校验，禁止脚本与任意注册表操作。
- RuleCompiler：匹配应用指纹，展开有界路径，编译为统一 Rule。
- RuleConditionEvaluator / Engine：按名称、年龄和大小的 AND 条件扫描；清理前重新核验范围、条件、文件身份和占用状态。
- RulePreview：仅调用扫描器，显示候选，不调用清理器。

Schema 1 原文与签名保持不变，依据文件名建立标识；规则执行 ID 按文件隔离。Schema 2 增加 PackId、Name、Author、Description 与 Conditions。示例见 [RulePack.template.json](../rules/RulePack.template.json)，完整中英填写说明见 [JSON规则填写说明.txt](JSON规则填写说明.txt)。旧 [ApplicationRules.template.json](../rules/ApplicationRules.template.json) 可与新格式一样通过 JSON 规则库批量导入。

## 扫描执行与本地缓存

ScanSession 将一次常规扫描的应用发现、规则匹配和文件检查串联，所有来源继续编译为统一 Rule。Engine 按需枚举目录，在单次扫描内共享重叠路径的目录条目与文件身份快照；最多保留 20,000 个条目及快照，结束或取消后释放。不会通过并行堆叠磁盘请求加速。

本地缓存默认启用，仅复用应用元数据和个人文件头识别结果，不保存规则、候选列表或删除授权。存储于 %LOCALAPPDATA%\ClearSpace\ScanCache\metadata.dat，使用当前用户 DPAPI 保护，上限 4,096 条、4 MB 明文，条目七天过期，软件版本或构建变化时重新识别。程序指纹按卷、文件 ID、大小和时间校验；RequireSignature 规则始终重新验证程序签名。文件分类按大小、修改时间和创建时间校验，仅为扫描提示；实际清理仍重新执行文件头保护、文件身份、年龄、范围和占用校验。

每次扫描重新枚举目录并读取文件信息、规则和进程状态。关闭缓存可强制重新识别；损坏、不可读或保存失败时回退到实时扫描，取消不会提交半次扫描。没有常驻文件监听、后台扫描或联网缓存。进度更新节流约每 160 ms 一次，末项立即报告。ScanStatistics 提供读取次数、复用次数与耗时，用于在隔离夹具上比较。

## 规则包管理

当前 JSON 来源存储在 %LOCALAPPDATA%\ClearSpace\Rules，Winapp2 存储在同级 Winapp2；两者分别更新和回退。导入文件存储在同级 RulePacks，每包一份记录，包含当前原文、上一版原文及启用开关，通过临时文件和原子替换保存。支持一次导入多个 Schema 1 / 2 文件，新文件默认关闭，同 PackId 仅允许更高版本导入；回退保留被替换版本。移除仅删除包定义，不清理应用缓存或备份。

导入文件损坏时跳过并显示原因；未知路径、链接、保护目录或格式错误不会产生清理目标。最多 20 包、每包 500 条规则。Schema 2 规则不提供绕过保留期或敏感保护的手动删除；所有 JSON 规则强制先备份。

## 发布与更新

Winapp2 使用项目固定 HTTPS 地址；当前 JSON 来源仅接受与内置公钥匹配的发布者签名包，用户可保存独立地址。自动检查为每个启用来源独立设置，每 7 天检查一次。JSON 规则库通过本地导入升级。没有 JSON 发布地址时可离线导入；不会上传应用列表或扫描结果。

发布者可使用 scripts/Publish-Rules.ps1 将 Schema 1 或 2 包封装为 Payload / Signature。客户端在验证签名后仍执行完整格式与安全校验。私钥应保存在仓库之外，不加入源码包或下载包。
